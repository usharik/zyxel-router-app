# Zyxel Router

Приложения для macOS и Android для роутера Zyxel VMG8623-T50B (прошивка V5.50(ABPM.7.3)V1): состояние интернета, устройства в сети, сети Wi-Fi, перезагрузка.

- `macos/`: SwiftUI, сборка и установка: `macos/build_install.sh` (нужны только Command Line Tools).
- `android/`: Kotlin и Compose, сборка: `cd android && ./gradlew :app:assembleDebug`, публикация: `tools/publish_apk.sh`.
- `mock/mock_router.js`: тестовый двойник роутера (логин admin / testpass).

## API роутера

База `https://<ip>/`, сертификат самоподписанный, порт 80 не отвечает. Описание получено из JS веб-интерфейса.

Без входа: `GET /getBasicInformation`, `/getRSAPublickKey`, `/getWebGuiFlag`.

Вход, `POST /UserLogin`:
1. Создать 32 случайных байта ключа AES и 32 байта IV, оба в Base64.
2. Тело `{Input_Account, Input_Passwd: base64(пароль), currLang, RememberPassword: 0, SHA512_password: false}` зашифровать AES-256-CBC (PKCS7, из IV берутся первые 16 байт).
3. Отправить `{content: base64(шифротекст), key: base64(RSA-PKCS1(строка Base64 ключа AES)), iv}`.
4. Ответ зашифрован тем же ключом и содержит `sessionkey`. Сессия хранится в cookie.

Запросы `/cgi-bin/*`: ответы приходят как `{content, iv}` с тем же ключом. POST, PUT и DELETE требуют заголовок `CSRFToken: <sessionkey>`, а непустое тело шифруется как `{content, key: "", iv}`. Ошибки входа: `Invalid Username or Password`, `Locked User` (`replyMsg` с секундами).

Основное: `/cgi-bin/DAL?oid=<oid>`, ответ `{result: "ZCFG_SUCCESS", Object: [...]}`. Используются `cardpage_status` и `lanhosts`. Есть также `wlan`, `wan`, `lan`, `static_dhcp`, `paren_ctl`, `nat`, `qos_*`, `firewall_*`, `zlog` и другие. Действия: `POST /cgi-bin/Reboot`, `POST /cgi-bin/UserLogout`.

Осторожно: `cardpage_status` возвращает пароли Wi-Fi в `WiFiInfo[].wifiPassword`. В снимок состояния, диагностику и телеметрию они не попадают. Android-приложение запрашивает пароль одной сети только при открытии окна «Поделиться» (QR-код) и держит его, пока окно открыто.

## Сборка macOS без Xcode

В SDK 27 `@State` является макросом, а его плагин есть только в Xcode, поэтому состояние экранов хранится в `ObservableObject`.

## Родительский контроль и маршрутизация

Родительский контроль читается и полностью редактируется (общий тумблер, создание, изменение, удаление профилей, вкл/выкл). Маршруты пока только для чтения.

- `paren_ctl`: Object[0] — общий статус (`PrentalCtlEnable`, `MaxLenPrentalCtlPrf`), далее профили (`Index`, `pcpEnable`, `pcpName`, `MACAddressList`, `Days`, `TimeRangeList`, `NetworkServiceList`, `URLFilter`). Общий тумблер: PUT `{PrentalCtlEnable:"1"|"0"}`. Профиль: читать объект, менять поля, PUT целиком с `Index`. Создание — POST без `Index` (роутер назначит). Удаление — DELETE `?oid=paren_ctl&Index=N` без тела. `Days` отправляется массивом, читается строкой через запятую; `MACAddressList` — через запятую с двоеточиями; `TimeRangeList` — `ЧЧ:ММ-ЧЧ:ММ` (до 3 интервалов). До 32 устройств и до 3 интервалов в профиле. При включённом Mesh роутер может не давать добавить профиль.
- `static_route`, `dns_route` (до 20), `policy_route`, `rip`: читаются для показа. POST добавляет, PUT меняет целиком, DELETE по `Index`.

### Важные замечания по записи

- **Токен сессии вращается:** каждый успешный POST/PUT/DELETE возвращает новый `sessionkey`; клиент подхватывает его из любого ответа, иначе следующая запись вернёт 403.
- **Тело записи шифруется:** непустое тело `/cgi-bin/*` отправляется как `{content: AES(тело), key: "", iv}` тем же ключом AES, что получен при входе. DELETE идёт параметром `?Index=N` без тела.
- **Одна сессия на пользователя:** второй вход получает «Duplicated login»; при параллельном входе через браузер приложение надо выводить из системы. Простой сессии роутера — около 5 минут.
- **Чтение после записи:** приложения перечитывают раздел после каждого изменения.
- **Безопасность:** в отчёте SEC Consult (эндпоинты `login_privilege`, `mgmt_srv`) исправление в прошивке V5.50(ABPM.6)C0; на роутере стоит V5.50(ABPM.7.3), то есть новее.

## Исправления по многомодельному ревью (Opus, Sonnet, codex gpt-6-astra)

- Редактирование профиля больше не стирает фильтры сайтов/сервисов и прочие поля: при изменении читается текущий объект, правятся только название, устройства, дни, время, флаг.
- Время сравнивается числами (минуты), дополняется ведущими нулями; `9:00` больше не отвергается как позднее `10:00`. Ночной интервал (начало позже конца) пока задаётся двумя профилями.
- Android: доступ к сессии сериализован (`@Synchronized`), устранены гонки cookies/CSRF между опросом и действиями пользователя.
- Устойчивый разбор: один не-объект в массиве роутера не обнуляет весь список (Swift); битый RSA-ключ не роняет приложение; короткий IV не дополняется нулями молча (Android).
- Полоса Wi-Fi определяется по стандартам (a/ac/ax → 5 ГГц), а не только по позиции в массиве.
- Ошибка записи и ошибка перечитывания разделены: повторная отправка не создаёт дубль.
- Сброс данных и редактора при выходе/перелогине; перехват ошибок Keystore/RSA при входе; баннер перезагрузки не затирается при опросе.

## Не закрыто (нужна проверка на живом роутере или вне объёма)

- Формат записи (`Days` массивом, MAC с двоеточиями, `TimeRangeList`, допуск `24:00`) взят из веб-интерфейса, на реальном роутере не сверялся захватом трафика.
- TLS доверяет любому самоподписанному сертификату приватного IP (без пиннинга) — осознанный компромисс для LAN.
- Несколько интервалов времени и фильтры сайтов/сервисов в UI пока не редактируются (сохраняются как есть). Маршруты только для чтения.

## Проверка на реальном роутере и фикстуры (2026-11-08)

Инструмент `macos/.build/debug/routercapture <ip>` входит на роутер, снимает ответы всех разделов в
санитизированные фикстуры (`fixtures/real/`, пароли/MAC/IP/имена обезличены с сохранением формата) и печатает
отчёт о формате. Флаг `--write-test` дополнительно создаёт ВЫКЛЮЧЕННЫЙ профиль с устройством (по умолчанию
с «media» в имени; задаётся `MEDIA_MATCH`), проверяет round-trip и удаляет его — обратимо, ничего не блокирует.

Запуск (пароль из Связки ключей, в вывод не попадает):
`ROUTER_PASSWORD="$(security find-generic-password -s com.usharik.routermanager -w)" macos/.build/debug/routercapture 192.168.1.1 --write-test`

Что подтверждено на живом VMG8623-T50B:
- Запись профиля роутер принимает в нашем формате: `Days` отправляется массивом, роутер хранит и возвращает
  СТРОКОЙ («Mon»); `MACAddressList` с двоеточиями; `TimeRangeList` вида «09:00-10:00». Роутер сам добавляет
  `ScheduleRuleList` — наше слияние при редактировании его сохраняет. Предел профилей = 12.
- Обратимый тест с «home-media-server»: профиль создан (выключенным), прочитан (дни и устройство совпали) и
  удалён — роутер вернулся к исходному состоянию.
- Разбор реального снимка: LAN приходит как `Srv=Default, Link=None` (исключается из выбора WAN);
  `Layer1Interface` бывает и `WiFi.SSID.N` без префикса `Device.` (учтено при определении гостевой сети).

Фикстуры используются в тестах: Swift читает `fixtures/real/*.json`, Android — копии в `app/src/test/resources/real/`.

Про WireMock: сырой HTTP-захват для этого API бесполезен — тела зашифрованы AES/RSA со случайным ключом на
сессию и не воспроизводятся. Роль «записанного двойника» играет `mock/mock_router.js` (полное рукопожатие и
шифрование), приведённый к реальным формам, плюс санитизированные фикстуры реальных ответов.

## Подробности устройства (2026-11-08)

По нажатию на устройство открывается карточка со всеми полезными полями из `lanhosts`:
- **Тип** (иконка + подпись): выводится из `VendorClassID` и имени хоста — телефон/планшет, компьютер,
  принтер, ТВ-приставка, IoT. Прошивка тип напрямую не отдаёт (`X_ZYXEL_HostType` пуст).
- **Wi-Fi:** уровень сигнала (0–5), сигнал/шум (дБ), скорость канала (`X_ZYXEL_PhyRate`), стандарт (g/n/ac).
- **Трафик:** принято/отправлено (`X_ZYXEL_BytesReceived/Sent`), человекочитаемо.
- **Сеть:** IPv4, наличие IPv6, статический/DHCP, блокировка родительским контролем.
- **«Все поля»** — раскрывающийся список всех непустых полей устройства (технические идентификаторы скрыты).

Чего в этой прошивке нет: модель и версия ОС, бренд без базы OUI, иконки (поля приходят пустыми).

Тесты: вывод типа по реальным `VendorClassID` (android-dhcp, XEROX, MSFT, atvbox, udhcp), `formatBytes`,
и разбор расширенных полей на РЕАЛЬНОМ трафике из фикстур (ненулевые байты, сигнал 1–5, распознавание принтера
и Android). Swift: `swift run RouterKitTests` (75 проверок). Android: `./gradlew :app:testDebugUnitTest` (13 тестов).

## Журнал и ограничения для офлайн-устройств (2026-11-08)

**Журнал** (вкладка «Журнал»): читается системный лог роутера
`GET /cgi-bin/LogResult?action=GET_LOG&oid=RDM_OID_LOG_CLASSIFY&iid=[1,0,0,0,0,0]` (ответ — зашифрованный
JSON-массив строк). Каждая строка разбирается: `[категория] Mon DD HH:MM:SS facility.severity процесс: сообщение`.
- **Записи:** список с поиском по тексту и фильтром по важности.
- **Статистика:** агрегирование по дням/неделям/месяцам (переключатель), по важности (с цветом) и по категориям.
Проверено на живом роутере: 435 реальных записей разобраны, сводки по info/err/debug и tr69/dhcpc/dhcpd.

**Ограничения для офлайн-устройств:** в редакторе профиля родительского контроля теперь можно добавить
устройство, которого сейчас нет в сети — оно показывается строкой «не в сети», плюс поле ручного ввода MAC
(нормализация AA:BB:CC:DD:EE:FF, приём ":" и "-"). MAC из профиля, отсутствующие в текущем снимке, видны и снимаются.

**Чего пока нет — история трафика по периодам.** Роутер НЕ хранит историю трафика, только живые счётчики
(`X_ZYXEL_Bytes*`, `Traffic_Status`). Аггрегация трафика по дням/неделям/месяцам потребует, чтобы приложение
само периодически снимало счётчики, считало дельты (с учётом сбросов при переподключении) и хранило локально.
Это отдельная задача (локальное хранилище + фоновая выборка + графики); готов сделать следующим шагом.

Тесты: разбор журнала и агрегация по периодам/важности/категориям, нормализация MAC. Swift 94 проверки
(`swift run RouterKitTests`), Android 15 тестов (`./gradlew :app:testDebugUnitTest`).

## Офлайн-устройства и локальная история (2026-11-08)

Роутер выдаёт в `lanhosts` только активные устройства и быстро забывает отключившиеся (после
истечения аренды DHCP; `static_dhcp` на этом роутере пуст). Поэтому раньше проводной компьютер,
который давно не в сети, не показывался нигде — его просто нет в данных роутера.

Что сделано:
- Список устройств по умолчанию показывает и офлайн (переключатель «Только в сети» выключен).
- **Локальная история**: приложение запоминает каждое увиденное устройство (MAC, имя, тип, когда
  последний раз было в сети). Когда роутер его забывает, оно остаётся в списке как офлайн с подписью
  «был: …». Хранится локально (macOS — UserDefaults, Android — SharedPreferences), до 200 записей на роутер.
- Офлайн/известные устройства можно выбрать в профиле родительского контроля; для совсем неизвестных —
  ручной ввод MAC. В карточке офлайн-устройства есть кнопка «Забыть».

Ограничение: устройство, которое роутер уже забыл И которого приложение ни разу не видело, задним
числом не появится. Решения: подключить его один раз при открытом приложении (запишется и останется),
либо добавить в профиль по MAC вручную.

Тесты: фабрика офлайн-устройства (online=false, сеть по типу подключения). Swift и Android.

## Обновление 1.1: размеры интерфейса и надёжность записи

- Android: интерфейс проверен на ширине 320–800 dp, с системным шрифтом до 2× и в альбомной ориентации. На невысоких экранах вкладки стоят в верхней панели, все шесть видны без прокрутки.
- Родительский контроль: время задаётся через выбор времени, учитывается лимит профилей роутера, открытые диалоги переживают поворот экрана.
- Запись при устаревшем CSRF-токене (HTTP 401/403/504) входит заново и повторяется один раз; создание профиля и перезагрузка не повторяются автоматически, чтобы не выполнить их дважды. Опрос эту ситуацию не видит: чтению токен не нужен.
- Ошибка записи держится на экране, пока запись не пройдёт или её не закроют; фоновый опрос её не стирает.
- `Days` при переключении профиля отправляется массивом — как при создании. Формат PUT на живом роутере ещё не проверен.
- Фикстуры обезличены строже: серийный номер, данные авторизации оператора, публичный IPv6-префикс, link-local адреса. `routercapture` скрывает их через `isSensitiveKey`/`anonymizedIPv6`; тесты падают, если такие значения появятся снова.

Тесты: Android `./gradlew :app:testDebugUnitTest` (34) и UI-тесты разметки `./gradlew :app:connectedDebugAndroidTest` (45, нужен эмулятор); macOS `swift run RouterKitTests` (144 проверки).

## Версия 1.2: подготовка к Google Play

- **Сертификат роутера закрепляется при первом подключении** (TOFU, SHA-256). Раньше TLS принимал любой сертификат: так безопасность хуже, и сканер Google Play отклоняет такие приложения («небезопасный X509TrustManager»). Если сертификат сменился (сброс, прошивка, подмена), вход останавливается, а на экране входа появляется кнопка «Доверять новому сертификату».
- **Firebase** (Analytics + Crashlytics) включается, если есть `android/app/google-services.json`. Без него приложение собирается и работает без Firebase. В событиях нет адресов, имён и логинов, из текстов ошибок вырезаются IP и MAC (`Telemetry.kt`). Debug-сборки ничего не отправляют.
- **Реклама AdMob и согласие GDPR (UMP).** Баннер внизу главных экранов, над вкладками и с отступом от них. Его нет на экране входа и в альбомной ориентации телефона. Полноэкранная реклама показывается только в паузах: после команды перезагрузки и после каждого третьего сохранённого изменения родительского контроля. В первые сутки после установки её нет, потом не чаще раза в 20 минут, и только если реклама уже загружена. Правила собраны в `AdPacing` (`Monetization.kt`) и покрыты тестами.
- **Разовая покупка `remove_ads`** (Play Billing 9): пункт меню, карточка на «Обзоре» после 5 подключений (затем раз в месяц), предложение сразу после закрытой рекламы (не чаще раза в неделю), раздел «О приложении» с восстановлением покупки.
- Просьба оценить в Google Play (In-App Review): после 4 подключений, раз за версию, не в одну сессию с рекламой.
- Release-сборка: R8 и сжатие ресурсов, подпись из `android/keystore.properties`. Задача `checkReleaseConfig` не даёт собрать release с тестовыми ID AdMob.
- **Поделиться сетью Wi-Fi по QR-коду:** кнопка у каждой сети на вкладке Wi-Fi (основной, гостевой, 2,4 и 5 ГГц). Окно показывает QR-код в формате `WIFI:T:WPA;S:…;P:…;;` (его понимают камеры Android и iOS) и скрытый пароль с кнопками «показать» и «скопировать». «Поделиться» отправляет PNG через системное меню вместе с текстом, в котором есть имя сети и пароль. Пароль запрашивается у роутера при открытии окна, сеть сверяется по месту и имени, пароль никуда не сохраняется (`WifiShare.kt`, `WifiShareDialog.kt`). Для сетей 802.1X (Enterprise) кнопки нет: по QR к ним не подключиться. Только WPA3 кодируется как `T:SAE`, смешанный WPA2/WPA3 — как `WPA`.
- Тематический значок Android 13+, Fastlane-лейн `internal`, `tools/play-remove-ads-product.rb`, черновик политики конфиденциальности и карточки магазина в `store/`.

Что сделать вручную перед публикацией: `store/README.md`.

### Исправления по ревью (1.2)

- **Демо-режим** («Попробовать без роутера» на экране входа): `DemoRouter` отдаёт встроенные данные через те же разборщики, что и настоящий роутер. Нужен проверяющим Google Play. Сохранённый пароль, отпечатки сертификатов и история устройств в демо-режиме не затрагиваются.
- **`RouterApi`**: интерфейс роутера. `RouterViewModel` получает фабрику клиента, поэтому тестируется на подставном роутере.
- **Сессия.** Фоновый повторный вход не повторяется, если роутер отказал или снова не отдаёт данные: опрос останавливается на экране входа, без риска блокировки учётки. Все запросы входа живут в области сессии и отменяются при выходе. Разделы «Контроль», «Маршруты» и «Журнал» при ошибке показывают «Повторить» вместо вечного индикатора. Маршруты читаются и тогда, когда часть разделов прошивка не поддерживает.
- **Сертификат.** Отпечаток закрепляется только после успешного входа (`SessionPins`); поиск роутера по адресу ничего не закрепляет. Без закреплённого сертификата сохранённый пароль сам не отправляется. «Доверять новому сертификату» закрепляет показанный пользователю отпечаток.
- **Реклама.**
  - Межстраничная показывается только если нет открытых окон и клавиатуры, а пользователь не касался экрана после действия (`AdPacing.interfaceIdle`).
  - Между баннером и вкладками 16 dp.
  - Повторы загрузки баннера останавливаются в фоне.
  - Купившим «без рекламы» форма согласия не показывается.
  - `AdsController` живёт в `ZyxelApp` и переживает поворот экрана.
- **Аналитика и Crashlytics** выключены до ответа формы согласия. В ЕЭЗ и Великобритании они включаются только с целью 1 TCF (`AdPacing.analyticsAllowed`).
- **Родительский контроль:**
  - MAC, введённый без «+», сохраняется;
  - MAC принимается в форматах `aabbccddeeff` и `aabb.ccdd.eeff`;
  - интервал «до 24:00» работает;
  - окно нельзя закрыть во время записи.
- **QR-код Wi-Fi:**
  - имена и пароли с `&`, `<` раскодируются;
  - PNG удаляется при закрытии окна и при запуске;
  - пароль копируется с пометкой «чувствительно».
- **Прочее:**
  - даты и числа на языке интерфейса (`locale_tag`);
  - отступы под вырез экрана;
  - подписи для TalkBack, контраст цветов;
  - короткая подпись под значком;
  - `dataExtractionRules`;
  - полоса Wi-Fi по `OperatingFrequencyBand`;
  - release не собирается без `google-services.json`, подписи и настоящих ID AdMob.

- **Второй раунд ревью (архитектура, тесты):**
  - выход и отказ во входе закрывают клиента: запросы из очереди не входят заново;
  - адрес принимается только как `IPv4[:порт]`, перенаправления выключены;
  - сбой разбора ответа — `BadResponse`, а не «недоступен», после него опрос не входит заново;
  - записи родительского контроля идут по одной;
  - реклама и просьба об оценке показываются только когда окно приложения на экране и в фокусе, а повод не старше 15 секунд;
  - решение по аналитике запоминается между запусками;
  - после блокировки входа приложение само не входит до её конца.
- **Найдено новыми тестами и исправлено:**
  - отпечаток всё ещё закреплялся при простом обращении к адресу (параметр конструктора перекрывал обёртку `SessionPins`);
  - падение при запуске из-за порядка инициализации в ViewModel;
  - release с R8 падал при запуске: Room 2.2.5 из AdMob, правило с конструктором в `proguard-rules.pro`.

Тесты: Android 109 unit (`./gradlew :app:testDebugUnitTest`) + 288 UI (`:app:connectedDebugAndroidTest`). В том числе:
- `RouterClientProtocolTest` — настоящий клиент против `mock/mock_router.js`, нужен Node; без него пропускается;
- `RouterViewModelTest` — сессия на подставном роутере;
- `DialogsTest` — QR-код, редактор профиля;
- `AppFlowTest` — запуск приложения и демо-режим целиком;
- `LocalizationTest` — тексты всех ошибок на 5 языках.

Release с R8 перед выпуском проверять вручную: `./gradlew :app:assembleRelease -PallowTestAds` (подпись debug-ключом), установить и пройти демо-режим. Инструментальные тесты идут на debug-сборке и R8 не видят.

### Локализация (1.2)

- Языки: английский (по умолчанию, `values/`), русский, украинский, чешский, немецкий. В Android 13+ язык приложения выбирается в системных настройках (`generateLocaleConfig`).
- Слой данных (`RouterClient`, `UiLogic`) возвращает коды: `DeviceType`, `WifiBand`, `RouteDetail`, `PeriodCount`, `ProfileError`, `Ago`, типизированные `RouterException`. Текст на языке пользователя строит `Localization.kt`. История устройств из 1.1 с русскими названиями типов читается через `DeviceType.parse`.
- Дни недели и месяцы — из `java.time`/ICU в форме `SHORT` и шаблона `LLLL`. На Android формы `*_STANDALONE` для ru/uk/cs/de возвращают номер вместо названия.
- `TranslationsTest` проверяет, что во всех языках одинаковые ключи и подстановки. UI-тест `LayoutFitTest` прогоняет вёрстку на всех пяти языках (270 случаев).
- Название в Play: «Router Manager for Zyxel»; тексты карточки — `android/fastlane/metadata/android/`, совместимые модели — `store/README.md`.

## Ежедневная диагностика (macOS, launchd)

`routerdiag` каждое утро проводит глубокую проверку роутера и связи и пишет отчёт в
`~/Library/Application Support/ZyxelRouter/diagnostics/latest.md` (архив — `reports/`, показатели для сравнения — `history/`),
а итог показывает уведомлением. Только чтение: на роутере ничего не меняется.

Установка: `macos/tools/install_diagnostics.sh [час] [минута]` (по умолчанию 08:00; если Mac спал, задание выполнится при
пробуждении). Запустить сейчас: `--run`, удалить: `--uninstall`. Пароль берётся из Связки ключей (сохраняется приложением
при входе с «Запомнить»), адрес и имя пользователя — из настроек приложения. Вручную:
`ROUTER_PASSWORD=… macos/.build/debug/routerdiag [ip] [--no-speedtest] [--no-notify] [--open]`.

Что проверяется:
- **С компьютера:** пинг до роутера и до 1.1.1.1/8.8.8.8 (задержка, джиттер, потери), DNS роутера с кэшем и без
  (случайное имя), публичный DNS для сравнения, время HTTPS, скорость загрузки/отдачи (speed.cloudflare.com; `DIAG_SPEEDTEST=0` отключает).
- **Роутер** (`cardpage_status`, `lanhosts`, `Traffic_Status`, `mgmt_srv`, `firewall`, `time`, `paren_ctl`, системный журнал и журнал атак):
  перезагрузки и смена прошивки с прошлой проверки, переподключения WAN, ошибка PPP, синхронизация DSL и её падение
  относительно медианы за неделю, ошибки/отбросы и трафик WAN за сутки (у PPPoE — по счётчикам `pppIfaceSt`), скорость
  и дуплекс портов LAN, состояние радио Wi-Fi и слабые клиенты, новые устройства, заполнение пула DHCP, открытое из интернета
  управление, межсетевой экран и DoS-защита, атаки за сутки, ошибки и обрывы связи в журнале, расхождение часов (важно для
  расписаний родительского контроля).

Роутер допускает одну сессию: если открыто приложение или веб-интерфейс, `routerdiag` повторяет вход до 4 раз с паузой 90 с.
Вне домашней сети (другой шлюз) отчёт отмечает это и не пишет показатели в историю.

Тесты: разбор `ping`/`dig`, оценка на реальных фикстурах (порт 10 Мбит/с, открытое управление, перезагрузка, новое устройство,
падение DSL, байты WAN с PPP-интерфейса, дата журнала на стыке лет) — `swift run RouterKitTests`.
