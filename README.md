# Zyxel Router

Приложения для macOS и Android для роутера Zyxel VMG8623-T50B (прошивка V5.50(ABPM.7.3)V1): состояние интернета, устройства в сети, сети Wi-Fi, перезагрузка.

- `macos/`: SwiftUI, сборка и установка: `macos/build_install.sh` (нужны только Command Line Tools).
- `android/`: Kotlin и Compose, сборка: `cd android && ./gradlew :app:assembleDebug`, публикация: `tools/publish_apk.sh`.
- `mock/mock_router.js`: тестовый двойник роутера (логин admin / testpass).

## API роутера

База `https://<ip>/`, сертификат самоподписанный, порт 80 не отвечает. Описание получено из JS веб-интерфейса.

Без входа: `GET /getBasicInformation`, `/getRSAPublickKey`, `/getWebGuiFlag`.

Вход, `POST /UserLogin`:
1. Создать 32 случайных байта ключа AES и 32 байта IV, оба в Base64.
2. Тело `{Input_Account, Input_Passwd: base64(пароль), currLang, RememberPassword: 0, SHA512_password: false}` зашифровать AES-256-CBC (PKCS7, из IV берутся первые 16 байт).
3. Отправить `{content: base64(шифротекст), key: base64(RSA-PKCS1(строка Base64 ключа AES)), iv}`.
4. Ответ зашифрован тем же ключом и содержит `sessionkey`. Сессия хранится в cookie.

Запросы `/cgi-bin/*`: ответы приходят как `{content, iv}` с тем же ключом. POST, PUT и DELETE требуют заголовок `CSRFToken: <sessionkey>`, а непустое тело шифруется как `{content, key: "", iv}`. Ошибки входа: `Invalid Username or Password`, `Locked User` (`replyMsg` с секундами).

Основное: `/cgi-bin/DAL?oid=<oid>`, ответ `{result: "ZCFG_SUCCESS", Object: [...]}`. Используются `cardpage_status` и `lanhosts`. Есть также `wlan`, `wan`, `lan`, `static_dhcp`, `paren_ctl`, `nat`, `qos_*`, `firewall_*`, `zlog` и другие. Действия: `POST /cgi-bin/Reboot`, `POST /cgi-bin/UserLogout`.

Осторожно: `cardpage_status` возвращает пароли Wi-Fi в `WiFiInfo[].wifiPassword`. Приложения их не читают и не показывают.

## Сборка macOS без Xcode

В SDK 27 `@State` является макросом, а его плагин есть только в Xcode, поэтому состояние экранов хранится в `ObservableObject`.

## Родительский контроль и маршрутизация

Родительский контроль читается и полностью редактируется (общий тумблер, создание, изменение, удаление профилей, вкл/выкл). Маршруты пока только для чтения.

- `paren_ctl`: Object[0] — общий статус (`PrentalCtlEnable`, `MaxLenPrentalCtlPrf`), далее профили (`Index`, `pcpEnable`, `pcpName`, `MACAddressList`, `Days`, `TimeRangeList`, `NetworkServiceList`, `URLFilter`). Общий тумблер: PUT `{PrentalCtlEnable:"1"|"0"}`. Профиль: читать объект, менять поля, PUT целиком с `Index`. Создание — POST без `Index` (роутер назначит). Удаление — DELETE `?oid=paren_ctl&Index=N` без тела. `Days` отправляется массивом, читается строкой через запятую; `MACAddressList` — через запятую с двоеточиями; `TimeRangeList` — `ЧЧ:ММ-ЧЧ:ММ` (до 3 интервалов). До 32 устройств и до 3 интервалов в профиле. При включённом Mesh роутер может не давать добавить профиль.
- `static_route`, `dns_route` (до 20), `policy_route`, `rip`: читаются для показа. POST добавляет, PUT меняет целиком, DELETE по `Index`.

### Важные замечания по записи

- **Токен сессии вращается:** каждый успешный POST/PUT/DELETE возвращает новый `sessionkey`; клиент подхватывает его из любого ответа, иначе следующая запись вернёт 403.
- **Тело записи шифруется:** непустое тело `/cgi-bin/*` отправляется как `{content: AES(тело), key: "", iv}` тем же ключом AES, что получен при входе. DELETE идёт параметром `?Index=N` без тела.
- **Одна сессия на пользователя:** второй вход получает «Duplicated login»; при параллельном входе через браузер приложение надо выводить из системы. Простой сессии роутера — около 5 минут.
- **Чтение после записи:** приложения перечитывают раздел после каждого изменения.
- **Безопасность:** в отчёте SEC Consult (эндпоинты `login_privilege`, `mgmt_srv`) исправление в прошивке V5.50(ABPM.6)C0; на роутере стоит V5.50(ABPM.7.3), то есть новее.

## Тесты

- macOS (без Xcode, только Command Line Tools): `cd macos && swift run RouterKitTests` — чистые функции разбора, имена сетей, определение полосы по стандартам, нормализация времени, приватные IP, крипто-самотест (AES с 32-байтным IV, отказ разбора битого RSA-ключа), отсутствие паролей в диагностике.
- Android: `cd android && ./gradlew :app:testDebugUnitTest` — те же проверки разбора на JVM (настоящий org.json).
- Интеграционно: `mock/mock_router.js` + `macos/.build/debug/routerprobe <ip>` с переменными `ROUTER_PASSWORD`, `ROUTER_CRUD` (создание/изменение/удаление профиля), `ROUTER_MERGE` (редактирование не стирает фильтры сайтов), `ROUTER_WRITE` (переключатели).

## Исправления по многомодельному ревью (Opus, Sonnet, codex gpt-6-astra)

- Редактирование профиля больше не стирает фильтры сайтов/сервисов и прочие поля: при изменении читается текущий объект, правятся только название, устройства, дни, время, флаг.
- Время сравнивается числами (минуты), дополняется ведущими нулями; `9:00` больше не отвергается как позднее `10:00`. Ночной интервал (начало позже конца) пока задаётся двумя профилями.
- Android: доступ к сессии сериализован (`@Synchronized`), устранены гонки cookies/CSRF между опросом и действиями пользователя.
- Устойчивый разбор: один не-объект в массиве роутера не обнуляет весь список (Swift); битый RSA-ключ не роняет приложение; короткий IV не дополняется нулями молча (Android).
- Полоса Wi-Fi определяется по стандартам (a/ac/ax → 5 ГГц), а не только по позиции в массиве.
- Ошибка записи и ошибка перечитывания разделены: повторная отправка не создаёт дубль.
- Сброс данных и редактора при выходе/перелогине; перехват ошибок Keystore/RSA при входе; баннер перезагрузки не затирается при опросе.

## Не закрыто (нужна проверка на живом роутере или вне объёма)

- Формат записи (`Days` массивом, MAC с двоеточиями, `TimeRangeList`, допуск `24:00`) взят из веб-интерфейса, на реальном роутере не сверялся захватом трафика.
- TLS доверяет любому самоподписанному сертификату приватного IP (без пиннинга) — осознанный компромисс для LAN.
- Несколько интервалов времени и фильтры сайтов/сервисов в UI пока не редактируются (сохраняются как есть). Маршруты только для чтения.

## Проверка на реальном роутере и фикстуры (2026-11-08)

Инструмент `macos/.build/debug/routercapture <ip>` входит на роутер, снимает ответы всех разделов в
санитизированные фикстуры (`fixtures/real/`, пароли/MAC/IP/имена обезличены с сохранением формата) и печатает
отчёт о формате. Флаг `--write-test` дополнительно создаёт ВЫКЛЮЧЕННЫЙ профиль с устройством (по умолчанию
с «media» в имени; задаётся `MEDIA_MATCH`), проверяет round-trip и удаляет его — обратимо, ничего не блокирует.

Запуск (пароль из Связки ключей, в вывод не попадает):
`ROUTER_PASSWORD="$(security find-generic-password -s com.usharik.zyxelrouter -w)" macos/.build/debug/routercapture 192.168.1.1 --write-test`

Что подтверждено на живом VMG8623-T50B:
- Запись профиля роутер принимает в нашем формате: `Days` отправляется массивом, роутер хранит и возвращает
  СТРОКОЙ («Mon»); `MACAddressList` с двоеточиями; `TimeRangeList` вида «09:00-10:00». Роутер сам добавляет
  `ScheduleRuleList` — наше слияние при редактировании его сохраняет. Предел профилей = 12.
- Обратимый тест с «home-media-server»: профиль создан (выключенным), прочитан (дни и устройство совпали) и
  удалён — роутер вернулся к исходному состоянию.
- Разбор реального снимка: LAN приходит как `Srv=Default, Link=None` (исключается из выбора WAN);
  `Layer1Interface` бывает и `WiFi.SSID.N` без префикса `Device.` (учтено при определении гостевой сети).

Фикстуры используются в тестах: Swift читает `fixtures/real/*.json`, Android — копии в `app/src/test/resources/real/`.

Про WireMock: сырой HTTP-захват для этого API бесполезен — тела зашифрованы AES/RSA со случайным ключом на
сессию и не воспроизводятся. Роль «записанного двойника» играет `mock/mock_router.js` (полное рукопожатие и
шифрование), приведённый к реальным формам, плюс санитизированные фикстуры реальных ответов.

## Подробности устройства (2026-11-08)

По нажатию на устройство открывается карточка со всеми полезными полями из `lanhosts`:
- **Тип** (иконка + подпись): выводится из `VendorClassID` и имени хоста — телефон/планшет, компьютер,
  принтер, ТВ-приставка, IoT. Прошивка тип напрямую не отдаёт (`X_ZYXEL_HostType` пуст).
- **Wi-Fi:** уровень сигнала (0–5), сигнал/шум (дБ), скорость канала (`X_ZYXEL_PhyRate`), стандарт (g/n/ac).
- **Трафик:** принято/отправлено (`X_ZYXEL_BytesReceived/Sent`), человекочитаемо.
- **Сеть:** IPv4, наличие IPv6, статический/DHCP, блокировка родительским контролем.
- **«Все поля»** — раскрывающийся список всех непустых полей устройства (технические идентификаторы скрыты).

Чего в этой прошивке нет: модель и версия ОС, бренд без базы OUI, иконки (поля приходят пустыми).

Тесты: вывод типа по реальным `VendorClassID` (android-dhcp, XEROX, MSFT, atvbox, udhcp), `formatBytes`,
и разбор расширенных полей на РЕАЛЬНОМ трафике из фикстур (ненулевые байты, сигнал 1–5, распознавание принтера
и Android). Swift: `swift run RouterKitTests` (75 проверок). Android: `./gradlew :app:testDebugUnitTest` (13 тестов).

## Журнал и ограничения для офлайн-устройств (2026-11-08)

**Журнал** (вкладка «Журнал»): читается системный лог роутера
`GET /cgi-bin/LogResult?action=GET_LOG&oid=RDM_OID_LOG_CLASSIFY&iid=[1,0,0,0,0,0]` (ответ — зашифрованный
JSON-массив строк). Каждая строка разбирается: `[категория] Mon DD HH:MM:SS facility.severity процесс: сообщение`.
- **Записи:** список с поиском по тексту и фильтром по важности.
- **Статистика:** агрегирование по дням/неделям/месяцам (переключатель), по важности (с цветом) и по категориям.
Проверено на живом роутере: 435 реальных записей разобраны, сводки по info/err/debug и tr69/dhcpc/dhcpd.

**Ограничения для офлайн-устройств:** в редакторе профиля родительского контроля теперь можно добавить
устройство, которого сейчас нет в сети — оно показывается строкой «не в сети», плюс поле ручного ввода MAC
(нормализация AA:BB:CC:DD:EE:FF, приём ":" и "-"). MAC из профиля, отсутствующие в текущем снимке, видны и снимаются.

**Чего пока нет — история трафика по периодам.** Роутер НЕ хранит историю трафика, только живые счётчики
(`X_ZYXEL_Bytes*`, `Traffic_Status`). Аггрегация трафика по дням/неделям/месяцам потребует, чтобы приложение
само периодически снимало счётчики, считало дельты (с учётом сбросов при переподключении) и хранило локально.
Это отдельная задача (локальное хранилище + фоновая выборка + графики); готов сделать следующим шагом.

Тесты: разбор журнала и агрегация по периодам/важности/категориям, нормализация MAC. Swift 94 проверки
(`swift run RouterKitTests`), Android 15 тестов (`./gradlew :app:testDebugUnitTest`).

## Офлайн-устройства и локальная история (2026-11-08)

Роутер выдаёт в `lanhosts` только активные устройства и быстро забывает отключившиеся (после
истечения аренды DHCP; `static_dhcp` на этом роутере пуст). Поэтому раньше проводной компьютер,
который давно не в сети, не показывался нигде — его просто нет в данных роутера.

Что сделано:
- Список устройств по умолчанию показывает и офлайн (переключатель «Только в сети» выключен).
- **Локальная история**: приложение запоминает каждое увиденное устройство (MAC, имя, тип, когда
  последний раз было в сети). Когда роутер его забывает, оно остаётся в списке как офлайн с подписью
  «был: …». Хранится локально (macOS — UserDefaults, Android — SharedPreferences), до 200 записей на роутер.
- Офлайн/известные устройства можно выбрать в профиле родительского контроля; для совсем неизвестных —
  ручной ввод MAC. В карточке офлайн-устройства есть кнопка «Забыть».

Ограничение: устройство, которое роутер уже забыл И которого приложение ни разу не видело, задним
числом не появится. Решения: подключить его один раз при открытом приложении (запишется и останется),
либо добавить в профиль по MAC вручную.

Тесты: фабрика офлайн-устройства (online=false, сеть по типу подключения). Swift и Android.
